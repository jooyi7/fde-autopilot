## 🚨 0. 과제 맥락이 모호할 때 쓰는 긴급 나침반 질문 (비상용)

### [우선순위 & 핵심 산출물 확정 질문]
```text
담당자님, 제한된 시간 내에 현업에서 가장 시급하게 필요로 하는 핵심 기능의 완성도를 극대화하고자 합니다. 이번 과제에서 반드시 완벽하게 동작해야 하는 1순위 핵심 산출물(Core Flow)과, 이번 1차 버전에서는 제외하거나 단순화해도 무방한 부가 기능의 경계를 짚어주실 수 있을까요?
```

### [문서/데이터 간 상충 조건 발견 시 질문]
```text
담당자님, 제공된 지시서(README)와 실제 샘플 데이터를 대조해보니 [특정 컬럼/조건] 부분에서 기준이 서로 다르게 해석될 여지가 있습니다. 현업 실무에서는 이 두 가지 중 어느 기준을 최우선(Single Source of Truth)으로 적용하여 판정하시나요?
```

## 📊 1. Type A Blueprint 대응: 센서 시계열 / 웨이퍼 수율 / 데이터 집계 과제
> **연동 블루프린트**: `blueprints/type_a_dashboard_fdc_wafer_yield.md`

### [A-1] 집계 단위(Granularity) 및 취소/테스트 건 제외 기준
```text
담당자님, 원천 데이터를 집계할 때 기본 단위가 개별 웨이퍼(Wafer) 기준인지 로트(Lot) 기준인지 확인하고 싶습니다. 아울러 상태값에 TEST, CANCELLED, HOLD 같은 비정상 플래그가 찍힌 레코드는 전체 처리 건수 및 수율(Yield) 계산 분모에서 완전히 제외하는 것이 맞을까요?
```

### [A-2] 결측치(Null) 및 센티널 이상치(-999 등) 처리 방식
```text
데이터를 프로파일링해보니 일부 센서 측정값에 빈 값(Null/NaN)이나 -999 같은 특수 결측 수치가 포함되어 있습니다. 현업에서는 이러한 행을 집계에서 아예 제외(Drop)하시나요, 아니면 직전 정상 측정값(ffill)이나 평균값으로 보정하여 처리하시나요?
```

### [A-3] 중복 데이터(Duplicate ID) 제거 우선순위
```text
동일한 식별자(Wafer ID 또는 Lot ID)로 여러 건의 측정 기록이 중복 유입된 케이스가 보입니다. 이 경우 가장 최근 타임스탬프(Latest) 1건만 유효한 데이터로 유지하면 될까요, 아니면 최초 발생 건을 기준으로 해야 할까요?
```

### [A-4] 임계치(UCL/LCL) 경계값 등호(`>=` vs `>`) 및 반올림 규칙
```text
정상/경고/위반 등급을 판정할 때, 측정값이 임계치(Threshold) 경계 숫자와 정확히 일치하는 경우(예: 기준이 100.0일 때 측정값도 100.0인 경우) 경고/위반에 포함(>=)되나요, 아니면 초과(>)할 때만 위반으로 보나요? 최종 수율이나 통계 수치의 소수점 반올림 자릿수 기준도 궁금합니다.
```

## 🔍 2. Type B Blueprint 대응: 스펙 Diff 검증 / 알람 SOP / 레거시 디버깅 과제
> **연동 블루프린트**: `blueprints/type_b_validator_diff_interview_alarm.md`

### [B-1] 기존 API 스키마 및 하위 호환성(Invariants) 유지 범위
```text
담당자님, 기존 시스템의 오류를 수정하고 검증 로직을 보강할 때, 현재 외부나 프론트엔드와 연결된 REST API 엔드포인트 경로와 응답 JSON의 필드 구조는 기존과 100% 동일하게 유지해야 하나요?
```

### [B-2] 다중 규칙 위반 시 우선순위 및 에러 리포팅 방식
```text
하나의 입력 데이터에서 여러 개의 스펙 위반(또는 금기어/알람 조건)이 동시에 감지될 경우, 가장 심각한 최우선 알람 1개만 반환해야 하나요, 아니면 감지된 모든 위반 사유를 배열 형태로 전부 리포팅해야 하나요?
```

### [B-3] 허용 오차(Tolerance) 및 대소문자/공백 정규화 기준
```text
레시피 파라미터나 텍스트 스펙을 비교(Diff)할 때, 앞뒤 공백이나 영문 대소문자 차이는 무시(Normalize)하고 비교하면 될까요? 수치 비교 시 부동소수점 미세 오차 허용 범위(Tolerance)가 따로 있는지도 확인 부탁드립니다.
```

## 📚 3. Type C Blueprint 대응: 사내 규정 / 매뉴얼 검색 및 출처 인용(RAG) 과제
> **연동 블루프린트**: `blueprints/type_c_policy_rag_citation_search.md`

### [C-1] 일반 조항 vs 예외 부칙 충돌 시 우선순위
```text
담당자님, 규정 문서를 분석해보니 본문의 일반 원칙 조항과 하단 예외 단서(또는 최신 개정 부칙)가 서로 충돌하는 사례가 있습니다. 판정 로직을 구현할 때 특별 예외 조항과 최신 개정일을 최우선으로 적용하여 판정하면 될까요?
```

### [C-2] 근거 조항 인용(Citation) 포맷 및 환각 차단(Out-of-Domain) 문구
```text
판정 결과를 출력할 때 근거가 되는 문서명과 조항 번호(예: 제3조 2항)를 어떤 형식으로 표기해야 현업 검토에 가장 편하신가요? 또한 제공된 규정집에 없는 질문이 들어왔을 때 추측을 배제하고 반환해야 할 표준 안내 문구(또는 '수동 검토 필요' 상태 코드)가 지정되어 있는지 궁금합니다.
```

### [D-1] 상태 전이(State Transition) 역행 제한 및 불변 조건
```text
담당자님, 설비 점검(PM)이나 티켓 상태가 [대기 -> 진행중 -> 완료/반려]로 전이될 때, 이미 '완료'나 '반려'로 확정된 건을 다시 이전 상태로 되돌리는 것을 시스템적으로 차단해야 하나요?

이번 과제 범위에서 별도의 복잡한 로그인/회원가입 없이 화면 내 역할 전환(또는 단일 관리자 뷰)만으로 핵심 상태 전이와 대시보드 기능을 모두 검증할 수 있게 구성해도 될까요? 또한 데이터 저장은 로컬 파일(JSON/SQLite)이나 세션 메모리 수준이면 충분한지 확인 부탁드립니다.
```
