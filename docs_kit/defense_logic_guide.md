# 🧠 후속 서술형 문항(5분/직접 타이핑) 방어 논리 가이드

> ⚠️ **주의:** 제출 확정 후 시작되는 후속 서술형에서는 **AI 사용 및 복사·붙여넣기가 전면 차단**되며 직접 타이핑해야 한다.
> 제출 버튼을 누르기 직전, 내가 구현한 **핵심 파일명 2개, 주요 함수명 2개, DM으로 확인한 예외 처리 1개**를 반드시 눈으로 기억하고 넘어갈 것!

---

## 💡 만능 3문장 답변 공식 (결론 $\rightarrow$ 코드/데이터 근거 $\rightarrow$ 예외 방어 및 한계)
모든 서술형 질문은 5분 안에 타이핑해야 하므로 **3~4문장(약 200~300자)**의 두괄식 구조로 간결하고 명확하게 작성한다.

### [유형 1] "특정 기능을 어떻게 구현했는가? 왜 그렇게 설계했는가?"
- **1문장 (핵심 구조):** 해당 기능은 수치 연산의 정확성을 보장하기 위해 `[파일명/함수명]`의 결정론적 로직과 UI/AI 계층을 분리하여 구현했습니다.
- **2문장 (구체적 동작):** 입력 데이터에서 `[필드명]`을 파싱한 뒤, `[기준값/조건]`을 기준으로 상태를 판별하여 일관된 결과가 도출되도록 처리했습니다.
- **3문장 (예외 방어):** 특히 결측치나 경계값 입력 시 시스템 오류가 발생하지 않도록 사전 검증(Fallback) 로직을 추가하여 안정성을 확보했습니다.

### [유형 2] "제공된 데이터의 문제점(결측치/충돌)을 어떻게 처리했는가?"
- **1문장 (탐지 내용):** 초기 데이터 스캔 과정에서 `[파일명/컬럼명]`에 결측치 및 포맷 불일치 데이터가 존재하는 것을 확인했습니다.
- **2문장 (처리 방식 및 근거):** 원본 데이터를 임의로 삭제하면 전체 통계가 왜곡될 수 있어(또는 업무 담당자와의 DM 확인을 거쳐), 파서 단에서 이를 별도의 예외 플래그로 분리하고 정상 데이터만 집계에 반영했습니다.
- **3문장 (화면 반영):** 분리된 이상 데이터는 사용자가 원인을 추적할 수 있도록 화면 내 별도 상태 표시로 확인할 수 있게 구성했습니다.

### [유형 3] "질문의 전제와 내 실제 구현이 다를 때" (가이드라인 8장 명시 사항)
- **가이드라인 핵심 규칙:** *"질문의 전제와 실제 구현이 다르면 차이를 밝히고 본인의 작업을 설명하세요."*
- **답변 템플릿:** "질문에서는 A 방식을 전제하셨으나, 실제 구현에서는 제한된 시간 내 정합성과 유지보수성을 높이기 위해 B 방식(`[실제 구현한 함수/방식]`)을 선택하여 구현했습니다. 이를 통해 `[기대 효과: 예-계산 오류 방지 및 즉시 렌더링]`을 달성했으며, 향후 A 방식으로 확장할 수 있도록 모듈을 분리해 두었습니다."

### [유형 4] "현재 구현의 한계점과 개선 방향은 무엇인가?"
- **답변 템플릿:** "현재 구현은 주어진 데이터셋 규모에서 정확한 판정과 빠른 응답을 보장하기 위해 인메모리 처리(또는 단일 프로세스) 기반으로 작성되었습니다. 만약 실무 환경에서 대용량 데이터가 실시간 유입된다면 DB 인덱싱과 비동기 큐(또는 서버사이드 페이지네이션)를 도입하여 성능을 고도화해야 합니다."
